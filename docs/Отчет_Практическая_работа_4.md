## 2. СИСТЕМА КОНТРОЛЯ ВЕРСИЙ И РЕПОЗИТОРИЙ

**Система контроля версий (СКВ)** — программное обеспечение для управления изменениями в исходном коде и других файлах проекта. Она позволяет отслеживать историю изменений, возвращаться к предыдущим версиям, работать в команде и разрешать конфликты при слиянии.

**Git** — распределённая система контроля версий, созданная Линусом Торвальдсом в 2005 году. Является наиболее популярной СКВ в мире.

**Репозиторий** — хранилище файлов проекта и истории их изменений. В Git репозиторий — это директория `.git`, содержащая все метаданные и объекты базы данных.

**Основные понятия Git:**
- **Commit (коммит)** — фиксация состояния файлов в репозитории с описанием изменений.
- **Branch (ветка)** — указатель на коммит, позволяющий вести параллельную разработку.
- **Merge (слияние)** — объединение изменений из разных веток.
- **Remote (удалённый репозиторий)** — версия репозитория на сервере (например, GitHub).

## 3. СОЗДАНИЕ РЕПОЗИТОРИЯ

### 3.1. Структура проекта

Для организации файлов проекта создана следующая структура каталогов:

```
WpfApp12/
├── src/          # Исходный код приложения
├── tests/        # Модульные и интеграционные тесты
├── docs/         # Документация (отчёты, описания)
├── resources/    # Ресурсы проекта (изображения, конфигурации)
├── WpfApp12/     # Основной проект WPF-приложения
│   ├── Data/     # Слой данных (EF Core, репозитории)
│   ├── Models/   # Модели предметной области
│   ├── Services/ # Бизнес-логика
│   ├── ViewModels/ # ViewModel (MVVM)
│   └── Views/    # Представления (XAML)
├── .gitignore    # Правила исключения файлов из Git
└── WpfApp12.slnx # Файл решения Visual Studio
```

**Обоснование структуры:**
- `src/` — содержит исходный код, отделённый от тестов и документации.
- `tests/` — тесты изолированы от основного кода для удобства запуска.
- `docs/` — документация хранится отдельно, что упрощает поиск.
- `resources/` — ресурсы сгруппированы в одном месте.

### 3.2. Настройка .gitignore

Файл `.gitignore` содержит шаблоны файлов и директорий, которые Git должен игнорировать. Для .NET проекта настроены следующие правила:

```gitignore
# Результаты сборки
bin/
obj/
*.user
*.suo

# Временные файлы IDE
.vs/
*.swp
*~

# Файлы ОС
Thumbs.db
Desktop.ini

# NuGet
packages/
*.nupkg

# Логи
*.log
```

**Обоснование:**
- `bin/` и `obj/` — результаты сборки, которые генерируются автоматически и не должны храниться в репозитории.
- `*.user` — пользовательские настройки Visual Studio.
- `.vs/` — временные файлы Visual Studio.
- `Thumbs.db` и `Desktop.ini` — системные файлы Windows.
- `packages/` — пакеты NuGet, восстанавливаемые автоматически.

## 4. ПЕРВЫЙ КОММИТ

Для создания первого коммита выполнены следующие команды:

```bash
# Инициализация репозитория
git init

# Добавление всех файлов в индекс
git add .

# Создание первого коммита
git commit -m "Initial commit: структура проекта, .gitignore, исходный код"
```

**Результат:**
- Создан репозиторий с первой фиксацией состояния проекта.
- Все файлы проекта (исходный код, документация, конфигурации) добавлены в историю.

## 5. ПРОВЕРКА СОСТОЯНИЯ

Для проверки состояния репозитория использована команда:

```bash
git status
```

**Результат:**
```
On branch main
nothing to commit, working tree clean
```

Это подтверждает, что:
- Все файлы зафиксированы в репозитории.
- Нет незакоммиченных изменений.
- Рабочая директория чистая.
